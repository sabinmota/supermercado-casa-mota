1 · Entrar y comprobar el terreno 30 min

1.1 · Compruebe la versión de Xcode ANTES de nada

Este dato decide qué versión de Capacitor puede usar. Abra Terminal (Launchpad → escriba «Terminal») y pegue:

xcodebuild -version
node --version

Apunte lo que salga. Si node dice «command not found», instálelo:

brew install node
DECISIÓN QUE DEPENDE DE ESE NÚMERO.
· Xcode 16 o superior → use Capacitor 7 (bloque 2, opción A)
· Xcode 15 → use Capacitor 6 (bloque 2, opción B)
· Xcode 14 o menor → no siga: pida otra máquina con Xcode reciente.

Instalar Capacitor 7 sobre un Xcode viejo falla al compilar, y el mensaje de error no dice que la causa sea la versión. Es la clase de fallo que consume dos horas.
1.2 · Clonar el repositorio
cd ~/Desktop
git clone https://github.com/sabinmota/supermercado-casa-mota.git
cd supermercado-casa-mota

Confirme que llegó todo:

ls index.html capacitor.config.json images/icons/
Corrijo un error de la guía vieja. app-store-assets.html línea 400 dice git clone .../TU_USUARIO/casamota.git — esa dirección no existe. La correcta es la de arriba.

2 · Capacitor y el proyecto iOS 45 min

🔴 NO EJECUTE npx cap init. NUNCA. La guía vieja lo manda en su línea 402 y es un error grave: ese comando sobrescribe capacitor.config.json, y su fichero ya contiene configuración que se perdería — server.url, los ajustes de iOS y los cuatro plugins (SplashScreen, StatusBar, PushNotifications, Keyboard).

Su proyecto ya está inicializado. Ese paso está hecho desde hace meses. Sáltelo.
2.1 · Crear el package.json que falta

Comprobado: su repositorio no tiene package.json. Sin él, npm install no sabe qué instalar. Créelo pegando este bloque completo de una vez:

cat > package.json <<'FIN'
{
  "name": "casamota",
  "version": "1.0.0",
  "private": true
}
FIN
2.2 · Instalar Capacitor — elija UNA opción

Opción A · si Xcode es 16 o superior:

npm install @capacitor/core@7 @capacitor/cli@7 @capacitor/ios@7

Opción B · si Xcode es 15:

npm install @capacitor/core@6 @capacitor/cli@6 @capacitor/ios@6
2.3 · Instalar los dos plugins nativos BUILD 432

Éstos son la respuesta a la directriz 4.2. Use la misma versión (@7 o @6) que eligió arriba.

Si eligió la opción A (Capacitor 7):

npm install @capacitor-mlkit/barcode-scanning
npm install @capacitor/push-notifications

Si eligió la opción B (Capacitor 6):

npm install @capacitor-mlkit/barcode-scanning@6
npm install @capacitor/push-notifications@6
🔴 NO MEZCLE VERSIONES. Capacitor 6 con plugins 7 falla al compilar, y el error no dice que la causa sea la mezcla. Es la clase de fallo que se come dos horas de reloj pagado.
2.4 · Generar la carpeta iOS
npx cap add ios
npx cap sync ios

Debe aparecer una carpeta ios/. Compruébelo:

ls ios/App/App.xcodeproj

Y confirme que los dos plugins entraron:

grep -i "barcode\|push" ios/App/Podfile

Debe listar los dos. Si no aparecen, npx cap sync ios no los recogió y hay que repetirlo.

Si cap add ios se queja de webDir: su configuración usa "webDir": ".", o sea la raíz del proyecto. Es correcto y a propósito, porque la app carga el sitio desde server.url y no necesita empaquetar los ficheros. No cambie ese valor.

3 · Icono y firma en Xcode 45 min

3.1 · Abrir el proyecto
npx cap open ios

Xcode tarda un par de minutos la primera vez. Espere a que termine de indexar (la barra de progreso de arriba).

3.2 · Poner el icono
  1. Suba su ZIP AppIcons a la Mac y descomprímalo
  2. En Xcode, panel izquierdo: App → App → busque Assets
  3. Dentro verá AppIcon. Bórrelo (clic derecho → Delete)
  4. Abra su carpeta AppIcons/Assets.xcassets en Finder
  5. Arrastre el AppIcon que hay dentro al panel Assets de Xcode
Nota sobre la carpeta: yo había predicho que el ZIP traería AppIcon.appiconset en la raíz. Su captura mostró Assets.xcassets, que es el envoltorio estándar de Xcode y contiene el AppIcon dentro. Entre en esa carpeta y arrastre lo que hay dentro, no la carpeta entera.
3.3 · Firmar
  1. Seleccione el proyecto App arriba del panel izquierdo
  2. Pestaña Signing & Capabilities
  3. Marque Automatically manage signing
  4. En Team elija su equipo (aparece si la cuenta está activa)
  5. Confirme que Bundle Identifier dice exactamente com.casamota.supermercado
Si en «Team» no aparece nada: su cuenta no está activa todavía. Xcode → menú Xcode → Settings → Accounts → + → inicie sesión con su Apple ID. Si sigue vacío, falta aceptar el acuerdo o pagar la membresía. No se puede continuar sin esto.
3.4 · Permisos de iOS BUILD 432

Abra documentos/permisos-ios-info-plist.txt del repositorio y pegue el bloque en ios/App/App/Info.plist. Las instrucciones exactas están en ese fichero.

🔴 SIN ESOS PERMISOS LA APP SE CIERRA SOLA AL ABRIR EL ESCÁNER. No sale ningún error: iOS mata el proceso en el instante en que una app pide la cámara sin haber declarado para qué la quiere. La app simplemente desaparece de la pantalla. Y Apple rechaza el envío si el texto falta o es genérico.
3.5 · Activar la capacidad de push

El Info.plist no basta:

  1. Proyecto App → pestaña Signing & Capabilities
  2. Botón + Capability
  3. Escriba Push Notifications y pulse Enter

Debe aparecer un bloque nuevo con ese nombre. Si esa opción no se ofrece, la cuenta no está activa.

3 bis · Comprobar que lo nativo funciona 15 min

Hágalo ANTES de las capturas y del Archive. Si el escáner no arranca, mejor saberlo con 3 horas de reloj por delante que en la última media hora.
Qué debe ver en la consola

Con la app corriendo en el Simulador: Safari en la Mac → menú Desarrollo → Simulator → su app. En la consola deben aparecer estas líneas:

[nativo] entorno nativo detectado: ios
[nativo] escáner nativo disponible: true
[nativo] push nativo disponible: true
🔴 SI DICE escáner nativo disponible: false, el plugin no se instaló bien. Vuelva al paso 2.3 y repita npx cap sync ios. No siga adelante: sin eso, la app no tiene nada nativo y el riesgo de la directriz 4.2 sigue intacto.
El escáner NO se puede probar de verdad en el Simulador: no tiene cámara real. Verá que se abre la interfaz de escaneo, y con eso basta para confirmar que el plugin responde. La lectura real de un código solo se puede probar en un iPhone físico.

El push tampoco llega en el Simulador — necesita un dispositivo real. Lo que sí se comprueba aquí es que el registro no da error.

4.1 · Arrancar el Simulador

En Xcode, arriba junto al botón ▶, elija el modelo. Pulse ▶ y espere.

4.2 · Capturar

Con el Simulador abierto: ⌘ + S guarda la captura en el Escritorio. Necesita 3 a 10 por tamaño. Sugerencia de qué mostrar:

  1. Catálogo de productos
  2. Una ficha de producto
  3. El carrito con artículos
  4. El checkout
  5. La tarjeta de puntos de fidelidad
Ojo con la primera pantalla. Su index.html exige sesión y redirige a login-cliente.html. Entre con demo@casamota.com / Demo2026 antes de capturar, o todas las capturas serán de la pantalla de acceso.

5 · Archive y subida 60 min

5.1 · Preparar

Arriba, en el selector de dispositivo, elija Any iOS Device (arm64). Con un simulador seleccionado la opción Archive aparece desactivada.

5.2 · Archivar y distribuir
  1. Menú Product → Archive (tarda 5-15 min)
  2. Se abre el Organizer → Distribute App
  3. App Store Connect → Upload → Next hasta el final
Si Archive falla: copie el texto del error y guárdelo. No lo interprete ni pruebe cambios al azar — mándemelo y lo leemos. Adivinar aquí cuesta horas de reloj pagado.

6 · Ficha y envío a revisión 60 min

Esto ya es en appstoreconnect.apple.com y puede hacerlo desde su PC: aquí ya no necesita la Mac. Si va justo de reloj, cierre la sesión de MacInCloud en cuanto la subida termine.

⚠️ El riesgo que sigue abierto

Con el icono resuelto, la directriz 4.2 es el único obstáculo grande que queda, y conviene saberlo antes de enviar.

A favorEn contra
✅ Escáner NATIVO (BUILD 432)
✅ Push NATIVO registrado (BUILD 432)
Tienda real: 1.979 artículos, carrito, pedidos, puntos
Credenciales demo listas y probadas
Privacidad y términos publicados
Empresa verificada por Apple		 server.url apunta a la web
limitsNavigationsToAppBoundDomains: true
El envío de push aún necesita clave APNs y servidor
El BUILD 432 cambió el equilibrio. Antes la columna «en contra» decía «ninguna función nativa activa» y el plugin de push estaba declarado pero sin usar ni una vez — comprobado con una búsqueda en todo el JavaScript: cero apariciones. Ahora hay escaneo nativo real con el motor del sistema, que en iOS es algo que un navegador no puede hacer.
Lo que sigue siendo un límite honesto: el push está registrado, no enviándose. Enviar exige una clave APNs de Apple y un servidor que firme cada envío; un sitio estático no puede firmar nada sin publicar la clave. Para la revisión de Apple esto es suficiente — evalúa que la app tenga capacidad nativa, no que usted haya mandado ya notificaciones.
